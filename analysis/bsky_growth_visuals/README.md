# Bluesky growth visuals

Generated by [`../growth_report.py`](../growth_report.py) from the
2026-05-11 snapshot (per-user state log + `actor_aggs`). Each chart is a
PNG (static, for posts) plus an interactive `.html`. `_data.json` holds
every computed aggregate behind the charts.

## Narrative order

| # | file | what it shows |
|---|------|---------------|
| 01 | `01_layer_cake` | retained users by acquisition cohort — the platform lives off the ≤2025-Q1 wave |
| 02 | `02_participation` | 2026-Q1 churn split by participation: 83% never create anything |
| 03 | `03_activity_dist` | distribution of posts / likes-given / follows per new user |
| 04 | `04_smile` | engagement "smile": active days in last 30 (one-off spike + near-daily core) |
| 05 | `05_first_like_cliff` | for creators, retention vs. likes received |
| 06 | `06_flow_attribution` | weekly in/out flow, churn split by tenure (new <90d vs active ≥90d) |
| 07 | `07_retention_metrics` | new-user 28-day activation vs. weekly active-base churn |
| 08 | `08_projection_*` | engaged-base projections to Dec-2027: vary retention / churn / volume / all-three (10×) |
| 09 | `09_active_survival` | cohort survival — % of active/super users still retained over 12 weeks (~80% at 3 months) |

## Regenerate

```sh
# from repo root, in a venv with modal + plotly + kaleido:
python -m modal run analysis/growth_report.py
```

One `modal run`: computes all aggregates remotely in a single window
pass over the state log + snapshot, then renders locally into this
folder. The heavy state machine is already cached in
`growth_state_log.parquet` on the volume, so this is minutes, not the
~40-min full pipeline.

## Tweaking the charts

- **Output location**: set `BSKY_VIZ_OUT=/some/dir` to render elsewhere.
- **Colors / titles / annotations**: all in `render()` in `growth_report.py`,
  one self-contained block per chart (`# 01 layer cake`, `# 04 smile`, …).
  Edit and re-run; no remote recompute needed if `_data.json` is current
  (see below).
- **Buckets / cohorts / thresholds** (e.g. the 3-month cohort grain, the
  90-day tenure split, the projection lever multipliers): in `compute()`
  and the projection block of `render()`.
- **Different snapshot**: change `DATE` at the top (needs a matching
  `growth_state_log.parquet` for that date on the volume).

### Render-only (skip remote recompute)

`render()` is pure-local and reads only `_data.json`. To iterate on
chart styling without re-hitting Modal, load `_data.json` and call
`render()` directly:

```python
import json
from analysis.growth_report import render
render(json.load(open("analysis/bsky_growth_visuals/_data.json")))
```
